# Contributing

Thanks for helping with `rtdlib`.

## Development

The minimum supported Rust version is 1.89. CI uses current stable as well. The published version tracks the TDLib release (`1.8.69` is TDLib 1.8.69). Pin it with `=`.

Compiling the generated types needs about 6 GB of RAM for one `rustc` process. See [Building](README.md#building) in the README. `cargo test --locked` does not link TDLib. `cargo test --features sys` does, and fails with `cannot find -ltdjson` until `libtdjson` is on the linker path.

```bash
cargo fmt --check
cargo test --locked
cargo clippy --locked --all-targets --features sys -- -D warnings
cargo audit
```

`rustfmt.toml` uses two-space indentation. Run `cargo fmt` before pushing. `src/types` is generated TDLib bindings; formatting-only edits there are fine, but behavior changes need a compatibility note.

The public Rust API should stay compatible with the 0.8.x line when the change allows it. `telegram-client` depends on these types and on the `sys` feature, which re-exports `rtdlib_sys::Tdlib`.

## What this crate is

Types are generated by [fantasy](https://github.com/fewensa/fantasy) from TDLib's `td_api.tl`. This repository does not contain the generator. From a fantasy checkout:

```bash
RTD_OUT=target/rtd-out cargo run --release -p fantasy
```

Copy `target/rtd-out/src/types` over `src/types`. Keep `src/lib.rs`, `src/errors.rs`, and the public `sys` re-export of `rtdlib_sys::Tdlib` stable when the schema allows it. A new TDLib schema is a new crate version and a CHANGELOG breaking section.

## Security

Report vulnerabilities privately. See [SECURITY.md](SECURITY.md). Do not file a public issue for a security report.
